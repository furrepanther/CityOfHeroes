# README BEFORE WORK — Base Editor De-Spaghettification (in-progress, uncommitted)

Read this before touching `Game/src/edit/`. It tells you what has already been
changed on this working tree, how to prove the changes are behavior-preserving,
and what is still unfinished.

## 1. What this work is

The City of Heroes base/map editor (the in-client editor under `Game/src/edit/`
plus `Game/src/editorUI.c`) is widely regarded as spaghetti: multi-hundred-line
monoliths, a shared `edit_state` god-struct, ~200 command bindings, and
file-scope statics reached from everywhere. The community avoids it.

This project **de-spaghettifies it in place, as C, with zero behavior change**.
It is deliberately NOT a rewrite (not in Python, not a new architecture): the
game client must keep building on Windows (VS2026, Win32, MSVC dialect). The
approach is surgical, reviewable extraction:

- decompose the monolith functions into small `static` helpers,
- de-duplicate copy-pasted blocks,
- replace unsafe/duplicated patterns (e.g. `_alloca` in a loop) with safe ones,
- leave the file layout, headers, public API, and observable behavior identical.

Extraction rules that were followed (keep following them):
1. Only extract leaves that are genuinely self-contained. If a value is a
   function-scope `static` used elsewhere in the same function, it stays put —
   do not hoist shared function-statics into a helper (this caused a real
   regression once; see §5).
2. New helpers must be `static` (the `.h` files are generated by `mkproto` from
   the `.c`, so a non-static helper would leak into the regenerated header).
3. Preserve C89-compatible block-start declarations and the existing dialect —
   no C99+ syntax, no new library dependencies.
4. Preserve dead code, odd formatting, and commented-out blocks verbatim where
   they are inert; do not "clean up" behavior-adjacent text.
5. No comments are added to the code (project rule for this effort).

### 4a. The syntax-check harness

Harness (already built in this environment; recreate it from the steps below if
`/tmp` was cleared — `/tmp` is not durable):


Its contents:

```bash
#!/bin/bash
# Editor syntax-check harness for CityOfHeroes (Win32, mingw-w64-i686)
ROOT=/linuxdata/Github/CityOfHeroes
f="$1"
[ -z "$f" ] && { echo "usage: check.sh <relative-file.c>"; exit 2; }

  -I "$ROOT/Game/src" -I "$ROOT/Common" -I "$ROOT/libs/UtilitiesLib/include" \
  -DCLIENT -DWIN32 -D_WIN32 -D_M_IX86 \
  "$ROOT/$f" 2>&1
```

Run it as:


### 4c. Proving an extraction is behavior-preserving (token diff)

For each extracted helper, diff the helper body against the master block it
replaced, after normalizing whitespace and substituting the parameter names.
Example used successfully for `pickColorDrawSlider` and `selUpdateRadii`:

```bash
cd /linuxdata/Github/CityOfHeroes
git show master:Game/src/edit/edit_select.c > /tmp/master_es.c
# then, in python: extract the master block by content markers
# (not by line number — line numbers drift), strip whitespace, replace
# regions[i].X / val_ptr etc. with the helper's parameter names, and
# difflib.unified_diff the two. Expected result: identical, except for the
# helper's own signature and any moved declaration lines.
```

Do not rely on line numbers from an earlier read: they shift as edits are
applied.

## 5. Known failure modes and their guards (read this — they already bit us)

1. **Interrupted extraction = call without definition.** A previous run wrote a
   helper *call site* (`pickColorPackOutput(...)`) and then never wrote the
   helper definition, leaving an implicit-declaration warning and a missing
   `if (!originalColorSet) { originalColorSet=1; originalColor=*color; }` block
   (master's only write to `originalColor`; losing it made cancel-restore
   return black). Both were repaired. 
   **Guard:** after every multi-part extraction, grep each edited file for
   `implicit declaration` via the harness. If a call has no definition, finish
   the extraction before doing anything else. Verify the surrounding block
   (especially `originalColorSet` / init-order blocks) survived.
2. **Hoisting a shared function-static into a helper.** This produced a real
   regression in an earlier attempt and had to be reverted. 
   **Guard:** before moving any function-scope `static` into a helper, grep the
   whole function for every other use of it. If it is read or written elsewhere
   in the function, keep it in the function and pass values in.
3. **Emitting tool-call text as prose.** In one run the agent printed
   tool-invocation-looking text as message text instead of making a real tool
   call, then repeated it in a loop. 
   **Guard:** make exactly one real tool call per step; never emit a tool tag as
   prose. See Memory Fabric `AG_RUNNER_TOOLCALL_PROSE_LOOP_V1`.
4. **Trusting line numbers across edits.** Line numbers shift after each edit;
   re-locate blocks by content markers.
5. **`external` declarations.** Block-level `extern` declarations inside a
   function (e.g. `extern int mouse_dy;`) are invisible to a helper you extract;
   re-declare as needed.
